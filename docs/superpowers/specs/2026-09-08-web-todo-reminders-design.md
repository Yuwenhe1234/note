# 今日待办网页提醒设计

## 目标

让“今日待办”在用户设定的时间通过网页内弹窗可靠提醒，不依赖浏览器系统通知权限。为后续 AI 陪伴的语音、动作或对话提醒预留统一的提醒事件订阅接口，但本次不实现 AI 陪伴行为。

## 范围与非目标

- 仅当网页处于打开状态时提醒；关闭网页、浏览器完全退出或设备休眠期间不保证触发。
- 当前提醒呈现为应用内的模态弹窗，不调用 `Notification` API，也不请求浏览器通知权限。
- 不修改待办数据结构：继续使用 `id`、`content`、`reminderTime` 和 `completed`。
- 不实现 AI 陪伴、桌面系统通知、重复提醒或跨天补发。

## 架构

新增独立的提醒调度服务，负责从今日待办计算下一次当天提醒、注册和取消计时器。服务在到点时发布一个结构化 `TodoReminderEvent`，其中包含待办 ID、内容、设定时间和触发时间。

网页层订阅该事件并将对应待办设为当前活动提醒，复用现有提醒模态框展示内容和确认按钮。确认只关闭弹窗；任务仍保持未完成。待办新增、编辑、完成或删除后，订阅层重新同步调度器，确保旧计时器被取消并依据最新数据安排。

后续 AI 陪伴通过同一服务注册事件监听器即可获得相同事件；它不读取页面状态，也不参与计时器管理。网页弹窗订阅者与未来 AI 陪伴订阅者相互独立。

## 调度规则

- 只调度拥有合法 `HH:mm` 提醒时间且尚未完成的待办。
- 仅为今天尚未来临的时间安排计时器；当前时刻或已过去的提醒不补发。
- 同一待办在单次同步中最多保留一个计时器；同步、完成、删除和卸载时都会取消旧计时器。
- 计时器触发后发布一次事件并移除自身，避免重渲染或重复同步产生多次弹窗。
- 多个待办同一时刻到期时，按调度事件依次显示；未确认的弹窗不被覆盖，后续事件进入队列。

## 错误处理与兼容性

- 不访问 `Notification`、`Notification.permission` 或 `Notification.requestPermission`，因此浏览器拒绝通知不会影响今日待办提醒。
- 不合法的提醒时间跳过调度，不阻断其他待办；时间选择器正常路径始终保存合法格式。
- 在非浏览器测试环境中，服务通过注入的时钟和计时器测试，不依赖 DOM 通知能力。

## 测试与验收

- 未授权、拒绝或不存在浏览器通知 API 时，到点仍发布网页提醒事件。
- 到点后出现网页提醒弹窗，且不创建系统通知。
- 编辑、完成或删除待办会取消其旧提醒；未来时间只触发一次。
- 同时到期的多个待办依次展示，确认当前提醒后展示下一项。
- AI 陪伴可通过提醒事件订阅接口收到事件，而无需修改调度或待办组件。
