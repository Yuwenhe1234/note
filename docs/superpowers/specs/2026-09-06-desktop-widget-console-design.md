# 桌面挂件控制台设计

## 目标

“放入桌面”卡片不直接启动挂件，而是进入独立的全页面配置控制台。用户确认显示内容和外观后，点击“运行桌面挂件”，Windows 桌面才显示按当前配置渲染的任务列表。

## 用户流程

1. 用户在“其他功能”点击整张“放入桌面”卡片。
2. 网站进入桌面挂件控制台，不显示额外的“调整设置”快捷按钮。
3. 用户调整内容、数量、透明度和外观模式，右侧预览实时更新。
4. 用户点击“运行桌面挂件”。
5. 浏览器调用本机 `/api/desktop-widget/open`，由本地服务直接启动预编译的 Windows 桌面助手；Tauri 客户端内则直接显示预加载窗口。
6. 桌面挂件读取同一账户的配置和任务数据并显示。
7. 用户可在挂件自身关闭；之后可再次从控制台运行。

## 控制台配置

- 显示今日待办：开关。
- 今日待办数量：1–20，仅在对应开关启用时可调。
- 显示任务清单：开关。
- 任务清单数量：1–20，仅在对应开关启用时可调。
- 透明度：60%–100%。
- 外观模式：跟随系统、深色、浅色；默认跟随系统。

所有配置写入当前工作区的 `desktopWidget` 字段，并由现有工作区保存流程持久化。主题新增 `theme: "system" | "dark" | "light"` 字段；旧数据缺少该字段时迁移为 `system`。

## 预览与桌面挂件

控制台右侧复用真实挂件预览组件。深色和浅色主题使用明确的背景、边框、文字和强调色；跟随系统使用 `prefers-color-scheme`。透明度仅改变挂件卡片背景视觉，不降低文字和按钮可读性。

最终桌面挂件与预览使用相同配置模型和主题类，避免两套渲染结果不一致。挂件保持无边框、跳过任务栏、可拖动、可关闭，并支持贴桌面/始终置顶切换。

## 启动行为

- 浏览器网站：点击“运行桌面挂件”调用本机启动接口，由 Vite 本地服务直接运行发布版助手，跳过浏览器外部协议确认。
- Tauri 客户端：点击按钮直接调用 `open_desktop_widget`。
- 控制台卡片本身只负责进入配置页，不触发系统协议。
- 启动失败时在控制台显示可读错误或提示，不离开配置页。

## 测试与验收

- 卡片点击进入控制台，且不会直接启动挂件。
- 控制台包含全部配置项和“运行桌面挂件”按钮。
- 主题默认值、旧数据迁移及三种模式切换有单元测试。
- 预览和桌面挂件使用相同主题配置。
- 浏览器协议与 Tauri 直接启动路径均有测试。
- 运行前端测试、类型检查、生产构建、Rust 测试和编译检查。
- 手动验收完整流程：进入控制台、调整配置、运行、桌面显示、挂件关闭、再次运行。

## 范围外

- 不实现开机自启。
- 不增加系统托盘菜单。
- 不在桌面挂件内部放置完整设置面板。
