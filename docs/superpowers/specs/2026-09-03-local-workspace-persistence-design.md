# 本地工作区持久化设计

## 目标

将任务清单、今日待办、用户设置和可编辑界面文字保存在项目目录的本地文件中，使数据不受浏览器刷新、端口变化、浏览器关闭或电脑重启影响。AI API 配置继续独立保存，并确保 API Key 不返回前端。

## 存储文件

### `.local/workspace-data.json`

```ts
type WorkspaceDataV1 = {
  version: 1;
  revision: number;
  updatedAt: string;
  tasks: Task[];
  todayTodos: TodayTodo[];
  settings: AppSettingsV1;
  editableText: {
    siteName: string;
    heroEyebrow: string;
    heroTitle: string;
    heroDescription: string;
    todayFocus: string;
  };
};
```

任务保存标题、说明、完成目标、优先级、步骤、步骤顺序、时长和完成状态。今日待办保存内容、提醒时间、完成状态和每日复用状态。

### `.local/workspace-data.backup.json`

每次覆盖正式文件前，将上一次有效数据保存为备份。正式文件无法解析时读取备份；两者都无效时返回明确错误，不用默认数据覆盖损坏文件。

### `.local/ai-config.json`

继续由现有 AI 配置服务管理服务商、模型、Base URL、启用状态和 API Key。公开接口只返回 `hasApiKey`，不返回密钥正文。`.local/` 保持在 `.gitignore` 中。

## 服务端接口

- `GET /api/workspace`：读取、校验和迁移工作区数据；不存在时返回 `data: null`。
- `PUT /api/workspace`：校验完整快照，递增 revision，先写临时文件，再备份旧文件并原子替换正式文件。
- 写入失败返回错误，保留原正式文件和前端当前状态。
- 服务端拒绝版本未知、字段类型错误或 revision 早于当前文件的写入，避免旧页面覆盖新数据。

## 前端加载

- 应用启动先显示加载状态，再请求 `GET /api/workspace`。
- 有工作区文件时，以文件内容恢复全部状态。
- 文件不存在时读取当前端口的旧 `localStorage`，组成首个工作区快照并保存。
- 如果文件和旧数据都不存在，才使用示例任务；示例任务只创建一次。
- 加载完成前禁止自动保存，避免初始空状态覆盖已有文件。

## 自动保存

- 任务、今日待办、设置或可编辑文字改变后，在 300ms 无新变化时提交完整快照。
- 同一时间只允许一次写入；写入期间发生新变化时，在本次完成后再保存最新快照。
- 页面显示“保存中 / 已保存 / 保存失败”状态。
- 保存失败不清空内存状态，并提供重试。

## 旧数据迁移

- 迁移当前来源中的 `memo-agent-today-todos`、设置、网站名称、首页三块文字和今日专注文案。
- 旧任务继续通过现有 `migrateTask` 处理分钟制、数字步骤和缺失目标字段。
- 迁移成功后记录 `memo-agent-workspace-migrated-v1`，但不立即删除旧 localStorage，保留一次回退机会。
- AI 自定义配置继续由 AI 配置文件迁移逻辑负责。

## 提醒恢复

- 工作区加载完成后，为未完成且时间未到的今日待办重新注册站内提醒。
- 已完成或已过期的待办不重新提醒。
- 每日复用待办跨天恢复时更新状态并保存新快照。

## 数据管理

- 现有导出功能改为导出完整工作区快照，但不包含 API Key。
- 导入前校验版本和结构；成功后写入本地文件并更新页面。
- “清空数据”只清空工作区数据，不删除 AI API 配置，除非用户单独执行“清除 AI 配置”。

## 验证要求

- 创建或编辑任务后刷新页面，内容保持。
- 更换端口后任务、今日待办、设置和文字保持。
- 关闭服务并重新启动后数据保持。
- AI API 配置保持且公开接口不泄露 Key。
- 损坏正式文件时能从备份恢复。
- 保存失败不会用空数据覆盖原文件。
- 首次迁移不会重复创建示例任务。
