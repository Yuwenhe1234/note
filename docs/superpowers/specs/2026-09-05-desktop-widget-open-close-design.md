# 桌面挂件开启与关闭设计

## 目标

完善“放入桌面”功能，使用户可以在网站配置页开启 Windows 桌面挂件，并可直接在挂件自身关闭它。关闭后不销毁窗口，网站下次开启时复用同一个窗口。

## 用户流程

1. 用户在网站的“放入桌面”页面点击“放入桌面”。
2. Tauri 客户端创建唯一的桌面挂件窗口；若窗口已存在但隐藏，则显示并聚焦它。
3. 挂件显示任务/今日待办预览，并提供关闭按钮。
4. 用户点击挂件关闭按钮后，窗口隐藏，主网站保持可用。
5. 用户返回网站再次点击“放入桌面”时，挂件重新显示，不创建重复窗口。

网页浏览器模式不创建原生窗口，而是显示明确提示，指导用户使用桌面客户端启动。

## 架构与数据流

- `DesktopConfigPage` 负责用户操作、调用状态反馈和配置保存，不直接依赖 Tauri 窗口实现。
- `widget-window.ts` 提供 `openDesktopWidget`、`hideDesktopWidget` 等窗口服务，并在非 Tauri 环境返回可识别结果。
- Tauri 后端以固定 label `desktop-widget` 管理单例窗口：打开时查找并显示已有窗口，否则创建新窗口；关闭时只执行 hide。
- 桌面挂件使用独立的窗口入口/查询标识渲染 `WidgetWindowRoot`，不显示主应用导航。
- 挂件通过工作区读取当前账户数据，并按固定间隔刷新；挂件内的关闭动作只影响窗口可见性。

## 窗口行为

- 无边框、透明、跳过任务栏，默认位于主屏幕右下角。
- 默认始终置顶；挂件内部的“贴桌面”按钮可切换到桌面图标上方的置底模式。
- 关闭按钮隐藏窗口，不退出应用、不删除配置、不清理窗口位置。
- 重复点击网站开启按钮必须幂等，不能产生多个挂件窗口。
- 窗口创建或调用失败时，网站展示可读错误信息；不吞掉 Tauri 错误。

## 配置与状态

桌面挂件的显示内容和样式配置继续保存到工作区的 `desktopWidget` 字段。开启/关闭属于原生窗口可见性，不新增持久化字段；因此关闭后网站仍可再次开启，刷新网站也不会误报为已显示。

## 测试与验收

- 单元测试覆盖浏览器模式下的 unsupported 回退、Tauri 下的打开/隐藏调用，以及重复打开结果。
- 组件测试覆盖网站按钮成功、已显示、浏览器提示和失败提示。
- 组件测试覆盖挂件关闭按钮调用隐藏服务。
- 运行全量测试、类型检查和生产构建。
- 在 Windows Tauri 开发模式手动确认：网站开启、挂件出现、挂件关闭、网站再次开启且无重复窗口。

## 范围外

- 不实现随 Windows 开机启动。
- 不实现系统托盘菜单。
- 不把桌面挂件关闭状态写入工作区。
