# 多服务商任务 AI 分析设计

## 目标

让新建任务的第二步调用真实大模型，自动生成任务摘要、优先级、总时长和可编辑的执行步骤；在设置页支持 OpenAI、DeepSeek、通义千问和智谱四类服务商。

## 首版范围

- 设置页新增 AI 服务商、API Key、Base URL、模型名称、启用开关和连接测试。
- API Key 不存入 React 状态、浏览器本地存储、构建产物或 Git。
- 本地 Vite 服务提供 `/api/ai/config` 与 `/api/analyze-task` 两个接口。
- 配置写入被 Git 忽略的本机配置文件，仅供本机启动脚本使用。
- 新建任务第二步展示分析中的状态、结果、错误和人工编辑入口。
- 支持统一的 OpenAI 兼容聊天调用，并由服务商配置决定地址、模型和请求差异。

## 非首版范围

- 公网部署、多用户账号、云端密钥管理和团队共享配置。
- 流式输出、长对话记忆、文件解析和联网搜索。
- 自动把 AI 结果直接保存为任务；用户必须确认结果后才保存。

## 服务商适配

| 服务商 | 配置策略 |
| --- | --- |
| OpenAI | 默认官方 API 地址与可修改模型名称；适配器预留后续 Responses API 升级路径。 |
| DeepSeek | 使用 OpenAI 兼容请求格式，只替换 Base URL、Key 与模型。 |
| 通义千问 | 使用百炼 OpenAI 兼容模式；允许用户填入所在地域或业务空间对应 Base URL。 |
| 智谱 | 使用标准 Bearer 认证与可配置模型；保留自定义 Base URL 以适配当前账户和模型套餐。 |

所有服务商都允许选择“自定义”，由用户自行填写 Base URL 和模型名称。

## 安全设计

浏览器只将 Key 通过本机回环地址发送给本地 Vite 服务。服务端把 Key 写入 Git 忽略的本机配置文件，后续调用时从本机读取；`GET /api/ai/config` 仅返回服务商、Base URL、模型和是否已配置 Key，不返回 Key 本身。

此方案仅适用于个人本机运行。发布到公网前，必须更换为独立后端与服务端密钥管理。

## 分析请求与结果

输入：任务名称、任务内容、时间长度、注意事项。

模型提示词要求只返回 JSON：

```json
{
  "summary": "string",
  "priority": "high | medium | low",
  "estimatedMinutes": 120,
  "steps": [
    { "title": "string", "minutes": 30 }
  ]
}
```

服务端校验：总时长为正整数、步骤数为 2–8、每步标题非空、每步时长为正整数。校验失败时向页面返回可读错误，而不是将不完整结果展示为分析成功。

## 页面交互

### 设置

1. 用户进入“设置 → AI 与 API”。
2. 选择服务商，自动带入建议 Base URL 与模型名称。
3. 填写 API Key，保存后输入框变为掩码状态。
4. 点击“测试连接”，显示成功、HTTP 错误、认证失败或模型不可用等结果。
5. 开启“任务 AI 分析”开关。

### 新建任务

1. 用户完成第一步信息并点击“下一步”。
2. 若未启用或未配置 AI，显示配置引导与手动编辑结果。
3. 若已配置，显示分析加载状态并调用 `/api/analyze-task`。
4. 成功后展示摘要、优先级、总时长和步骤；步骤标题与时长均可编辑。
5. 用户点击“确认并保存”后，结果写入任务清单。

## 错误与降级

- API Key 缺失：提示到设置页配置。
- 网络/超时/认证错误：显示错误原因，保留第一步输入。
- 模型非 JSON 或字段不完整：提示“结果格式异常”，允许重新分析或手动修改。
- 用户主动关闭弹窗：不保存任务、不清除已有配置。

## 验证

- 四个服务商预设均可选，并且自定义选项可用。
- API Key 不出现在设置读取接口、浏览器 localStorage、构建文件或 Git 状态中。
- 成功响应能生成可编辑步骤和总时长。
- 每种失败状态有明确提示且不丢失用户输入。
- 任务保存前后统计与任务清单保持联动。

## 工期

目标工期 2–3 小时：配置界面与本机存储约 45 分钟，接口适配与连接测试约 45 分钟，任务分析 UI 约 45 分钟，测试与错误处理约 30 分钟。
