# GitHub Pages 网页版与 Tauri 桌面版双版本设计

## 目标

将 MemoAgent 发布为任何人都能通过公开网址访问的网页，同时保留现有 Tauri 桌面客户端。网页版不要求注册或登录，不提供跨设备同步，也不依赖付费云服务器；每位访客的数据和 AI 配置保存在其当前浏览器中。

正式网页预计发布在 `https://yuwenhe1234.github.io/note/`。GitHub Pages 只承载静态前端，GitHub Actions 负责测试、构建和发布。

## 范围

### 网页版包含

- 任务清单、任务创建与编辑、步骤管理、今日待办和网页内提醒。
- 主题、强调色、可编辑文案和其他浏览器可用设置。
- 使用访客自备 API Key 的任务分析、今日待办生成和消息摘要。
- 今日消息界面、订阅资料管理、本地消息存储，以及手动添加标题、链接或正文并生成摘要。
- 工作区及设置的导入与导出。
- 通过 GitHub Pages 提供公开 HTTPS 网址。

### 网页版不包含

- 本地账户选择、注册、登录和云端数据同步。
- 自动抓取网站或内容平台、平台登录、后台浏览器和定时自动抓取。
- Tauri 原生窗口、置底透明桌面小组件、跳过任务栏和其他操作系统专属能力。

### 桌面版保留

- Tauri 客户端与桌面小组件。
- 当前本机账户、工作区服务和原生窗口能力。
- 自动抓取、平台登录和定时刷新等需要本机 Node/Playwright 服务的功能。
- 桌面版可以在后续独立通过 GitHub Releases 分发安装包；安装包发布不属于本次 GitHub Pages 上线范围。

## 总体架构

应用采用共享 React 界面加运行环境适配层的双版本结构：

1. 共享界面和领域模型继续位于 `src/`，任务模型、设置模型和大部分交互在网页与桌面之间复用。
2. 网页构建启用纯浏览器适配器：跳过认证门控，使用 `localStorage` 工作区仓库，使用浏览器 AI 客户端，并隐藏桌面专属操作。
3. 桌面开发模式继续使用现有 Vite 中间件、`server/` 路由与 Tauri API，不因网页部署而移除现有能力。
4. 环境差异通过明确的运行时能力检测或构建配置封装，不在各个组件中散布重复判断。

网页版是静态产物，不部署 `server/` 目录，也不在 GitHub Actions 或 GitHub Pages 中保存任何服务商 API Key。

## 浏览器工作区

网页版直接进入主应用，不呈现账户选择页。首次访问创建空工作区；之后从固定版本的浏览器存储键恢复工作区。

浏览器工作区至少保存：

- 任务和任务步骤。
- 今日待办及提醒设置。
- 应用设置、主题和可编辑文案。
- 桌面小组件的纯数据配置，以便导出兼容，但网页不调用原生窗口。
- 今日消息订阅资料、手动添加的消息、摘要和去重信息。

保存过程保持现有防抖行为。存储数据必须带版本号，并复用现有迁移函数读取旧格式。损坏数据不会覆盖当前内存状态；应用应提示用户导入备份或重置。浏览器存储空间不足时显示明确错误。

导出功能生成包含工作区和相关 `memo-agent-*` 设置的文件；导入前校验结构和版本，成功后再覆盖当前浏览器数据。界面提示用户：更换设备、浏览器、无痕窗口或清理站点数据不会自动迁移数据。

## 浏览器 AI 客户端

网页版的 AI 设置保存服务商、模型、接口地址和访客自己的 API Key。配置只写入当前浏览器，不写入源码、构建产物、GitHub Actions 变量或仓库。

AI 客户端直接调用用户选择的 OpenAI 兼容接口，并复用现有任务分析结构校验规则。AI 功能包括：

- 测试当前连接。
- 分析任务并生成步骤。
- 根据任务生成今日待办。
- 根据用户手动提供的消息正文生成结构化摘要。

设置页明确说明浏览器存储 API Key 的风险，建议只在可信设备上使用。错误提示区分未配置、认证失败、服务商不允许浏览器跨域请求、网络失败、限流和返回结构错误。调用失败不得清空用户输入或已保存工作区。

服务商是否允许浏览器跨域请求由服务商决定。某服务商阻止跨域时，网页版应解释原因并允许用户更换兼容接口；本项目不以代理服务器绕过该限制。

## 今日消息

网页版保留现有今日消息布局、订阅资料管理和本地消息仓库，但将刷新流程改为手动内容导入：

1. 用户选择或新建一个订阅来源。
2. 用户填写内容链接，并至少提供标题或正文之一。
3. 应用在浏览器中完成输入校验和本地去重。
4. 用户可直接保存消息，或使用自己的 AI 配置生成摘要后保存。
5. 摘要结果继续使用现有消息模型展示，并遵守现有三天清理规则。

网页界面不显示平台登录、后台抓取和定点自动刷新控件。相应位置说明自动抓取仅在桌面版提供。桌面版继续调用现有 `/api/news/*` 路由，网页版不会请求这些路由。

## 桌面专属能力

网页版隐藏或替换以下操作：

- “放入桌面”和原生窗口控制。
- 依赖本机协议注册或 Tauri `invoke` 的操作。
- 自动内容抓取和平台登录。

若保留桌面功能介绍，应使用不可误触的说明和桌面版下载占位，不呈现会失败的操作按钮。本次不创建或发布安装包。

## GitHub Pages 发布

建立 `main` 作为稳定发布分支，当前 `feat/desktop-widget` 继续承担开发用途。GitHub Actions 只在 `main` 更新时发布正式网页。

Vite 的生产构建基础路径设置为 `/note/`，确保 HTML、JavaScript、CSS 和静态资源在项目站点子路径下正确加载。本项目当前没有需要服务端回退的 URL 路由；若以后加入 History API 路由，需同时设计 GitHub Pages 的刷新回退方案。

部署工作流执行：

1. 检出 `main`。
2. 安装固定锁文件依赖。
3. 运行类型检查。
4. 单次运行测试套件。
5. 构建 GitHub Pages 网页产物。
6. 仅在前述步骤全部成功后上传并部署 `dist/`。

仓库 Pages 设置使用 GitHub Actions 作为发布来源。所有发布资源通过 HTTPS 提供。

## 错误处理

- 浏览器工作区读取失败：保留可操作页面，提示导入备份或重置，不静默覆盖损坏数据。
- 浏览器存储写入失败：显示未保存状态并提供导出建议。
- AI 配置缺失：引导用户进入设置，不发送请求。
- AI 请求失败：保留输入，显示可行动的分类错误，允许重试。
- 消息内容不足或重复：在保存或调用 AI 前阻止操作并定位问题字段。
- 桌面 API 在网页中不可用：能力适配层返回网页不支持状态，界面不触发无效请求。
- 部署构建失败：GitHub Actions 停止发布，继续保留上一个成功版本。

## 测试与验收

自动测试至少覆盖：

- 网页模式不请求 `/api/auth/*`，并直接渲染主应用。
- 浏览器工作区首次初始化、保存、刷新恢复、旧数据迁移和损坏数据处理。
- API 配置只写入浏览器存储，且任务分析、今日待办和消息摘要使用同一浏览器 AI 客户端。
- AI 未配置、认证失败、跨域或网络失败、格式无效时的用户提示。
- 今日消息手动输入校验、去重、摘要保存和三天清理。
- 网页模式不渲染或不启用 Tauri、平台登录、自动抓取和定点刷新操作。
- 桌面模式的既有认证、工作区、抓取和小组件测试继续通过。
- 使用 `/note/` 基础路径的生产构建成功，构建产物入口和静态资源路径有效。

上线验收标准：

- 未登录访客可通过公开网址进入应用并创建任务。
- 刷新页面后任务仍存在。
- 用户可以配置兼容服务商的自备 API Key，并完成连接测试和至少一次任务分析。
- 用户可以手动添加一条今日消息，并在配置 AI 后生成和查看摘要。
- 网页不会请求本地认证、工作区、新闻抓取或桌面组件接口。
- GitHub Actions 测试和构建通过后自动发布，失败时不替换线上版本。

## 安全与隐私

- 不在 GitHub 仓库或 Pages 产物中包含预置 API Key、Cookie、平台登录资料或 `.local/` 数据。
- 用户数据不上传到项目服务器；只有用户主动发起 AI 功能时，相应输入会发送给其选择的 AI 服务商。
- 外部链接使用防止 opener 劫持的打开方式。
- 手动消息正文按纯文本处理，不直接注入 HTML。
- 页面清楚说明浏览器本地保存、API Key 风险和数据清理后果。

## 非目标

- 云端账户、数据库、多设备同步和团队协作。
- 免费公共 AI Key 或由项目方代付的 AI 调用。
- GitHub Pages 上的自动网页抓取、平台登录或常驻定时任务。
- 将 Tauri 原生桌面小组件改造成网页能力。
- 本次发布桌面安装包或自动更新服务。
