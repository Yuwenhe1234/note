# 第二阶段功能开发设计

## 1. 目标

第二阶段在不改变现有主导航及既有交互风格的前提下，完善“今日消息”“AI 陪伴”和“拓展功能”三个彼此独立的功能。每个功能从“其他功能”入口进入当前网站内的二级功能页，并复用项目当前的颜色、字体、圆角、卡片、按钮和轻量动效风格。

本阶段的主要交付目标是可用的“今日消息”；“AI 陪伴”保留独立入口和后续设计；“拓展功能”完成插件中心与统一接入接口，不预装具体业务插件。

## 2. 范围与优先级

### 2.1 本阶段范围

1. 建设“今日消息”网站内二级信息中心页面。
2. 支持抖音、B站、小红书、YouTube 账号或 UP 主主页，以及普通网站地址作为订阅来源。
3. 支持在平台官方页面完成登录，并在本机保存登录会话。
4. 用户点击“刷新”时增量获取新内容，并通过现有大模型 API 生成摘要和要点。
5. 建设插件中心骨架、权限模型和统一接口。
6. 保留“AI 陪伴”二级页面入口与后续产品规划。

### 2.2 不在本阶段实现

- 不做后台定时抓取；只有用户点击“刷新”才检查新内容。
- 不批量导入订阅前的历史内容；首次刷新时仅为每个来源取最新 1 条作为起始消息。
- 不提供应用内收藏、归档或永久消息库。
- 不在本阶段开发照片、声音训练及真实桌面宠物能力。
- 不预装具体第三方业务插件。

## 3. 总体产品结构

现有主导航和“其他功能”入口保持不变。“今日消息”“AI 陪伴”和“拓展功能”分别进入当前网站内容区中的二级页面，顶部主导航继续保留，并提供“返回其他功能”。功能状态和业务数据不互相混合。

二级页面复用现有 Apple / Linear 风格设计令牌和通用组件，不建立另一套视觉体系。页面应具有一致的标题区、返回行为、加载状态、空状态、错误提示和键盘焦点样式。此阶段不创建浏览器弹窗或 Tauri 原生功能窗口；后续“放入桌面”另行设计。

## 4. 今日消息

### 4.1 用户流程

```text
从“其他功能”进入今日消息二级页面
  → 添加平台账号、UP 主主页或网站地址
  → 在平台官方页面扫码或登录
  → 保存订阅来源
  → 用户点击刷新
  → 首次刷新取该来源最新 1 条；后续刷新取上次成功刷新后发布的全部新内容
  → 每条内容完成整理和 AI 总结后直接显示完整消息卡片
  → 用户点击卡片或“查看原内容”跳转到原网站
  → 消息及相关缓存满三天后自动删除
```

首次添加来源时不立即拉取内容。用户第一次点击刷新时，每个来源只获取最新 1 条视频或文章，展示完整 AI 卡片并记录平台游标；之后每次刷新只处理上次成功刷新后发布且尚未保存的新内容。

### 4.2 页面布局

“今日消息”采用左右布局：

- 左侧为订阅来源列表，显示平台图标、账号或网站名称、地址、登录状态和最近成功刷新时间。
- 左侧支持添加来源、删除来源和重新登录。
- 右侧顶部显示“刷新”按钮、最近更新时间和本次刷新结果。
- 右侧主体按发布时间从新到旧显示消息卡片。
- 刷新期间按钮进入加载和禁用状态，避免重复任务。
- 每处理完一条新内容，完整卡片立即加入消息流，不必等待所有来源结束。

### 4.3 消息卡片

每张消息卡片包含：

- 封面或网站缩略图；
- 内容标题；
- 来源账号或网站；
- 原始发布时间；
- AI 摘要；
- 3～5 个重点；
- “查看原内容”按钮。

点击卡片或“查看原内容”时，使用系统默认浏览器打开原视频或文章地址。界面不提供收藏功能；用户在原平台完成收藏。

对用户而言，抓取、内容整理和 AI 总结属于一次完整刷新。界面不展示原始数据或“等待标准化”等中间卡片。某条内容只有在形成完整消息卡片后才显示。

### 4.4 登录与会话

- 登录必须在由本地采集服务启动的专用 Edge 窗口中打开平台官方页面或官方授权页面。
- 用户可扫码或在官方页面输入账号信息；该 Edge 窗口使用项目专属的持久化浏览器配置目录。
- 应用不读取、不记录账号和密码。
- 登录 Cookie 与浏览器会话仅由 Edge 保存在项目本机配置目录中，并按当前本地用户隔离；采集服务通过同一浏览器配置读取登录后的动态页面，不将 Cookie 返回给 React 页面。
- 会话失效时，在对应来源旁显示“需要重新登录”，不连续弹窗打断用户。
- 用户可主动退出某个平台并清除其本地会话。

### 4.5 采集架构

采用“本地采集服务 + 平台适配器”架构。网站二级页面负责交互和结果展示；本地采集服务负责登录会话、增量刷新、内容解析、去重、AI 总结和三天清理。

抖音、B站、小红书、YouTube 和普通网站分别使用独立适配器。平台规则变化时，只修改对应适配器，不影响消息界面及其他平台。

动态平台适配器通过 Playwright Core 控制本机已安装的 Microsoft Edge。点击登录时使用一个可见窗口完成官方登录；点击刷新时关闭可见登录上下文，并使用同一持久化配置目录启动后台无界面 Edge，等待作品列表渲染后读取真实作品链接，刷新过程中不得连续打开可见标签页。普通网站仍优先使用轻量 HTTP 与 HTML/Open Graph 解析；只有必须执行 JavaScript 时才使用浏览器采集。

抖音、B站、小红书和 YouTube 的平台根首页不是有效订阅来源，因为其中没有唯一账号。添加来源时必须校验为具体账号、频道或 UP 主主页。若未发现真实作品链接，刷新应返回可理解的来源错误，禁止把官网、账号主页或订阅主页本身生成消息卡片。

适配器统一输出以下标准字段：

```ts
type NormalizedContent = {
  platform: string;
  sourceId: string;
  sourceName: string;
  contentId?: string;
  url: string;
  title: string;
  publishedAt: string;
  thumbnailUrl?: string;
  text?: string;
  transcript?: string;
};
```

`NormalizedContent` 是内部适配器契约，不作为用户可见的独立处理阶段。

### 4.6 增量刷新与去重

- 添加来源成功时保存 `subscribedAt`，但不立即读取内容。
- 来源尚无 `lastSuccessfulRefreshAt` 或游标时，刷新结果按发布时间排序后只保留最新 1 条。
- 每个来源保存 `lastSuccessfulRefreshAt` 和可用的平台游标。
- 来源已有成功刷新记录后，只接受发布时间晚于上次成功刷新位置的新内容。
- 优先使用平台内容 ID 去重，同时使用规范化原链接作为第二重去重键。
- 同一轮刷新中的来源可并行处理；同一来源内部按平台限制控制并发。
- 只有来源刷新成功后才推进该来源的刷新位置，避免失败后漏掉内容。

### 4.7 AI 总结

“今日消息”直接复用项目设置中已经配置的大模型服务、模型和参数，不增加独立 API 配置。

- 视频优先使用平台字幕或可合法取得的文本信息；没有字幕时使用标题、简介及其他可取得的正文信息。
- 文章提取标题和正文后生成摘要。
- 统一输出简短摘要和 3～5 个重点。
- AI 未配置时保留待处理内容并提示前往设置，不显示缺少摘要的半成品卡片。
- 单条总结失败时自动进行有限次数重试；仍失败则计入刷新结果，并允许用户再次刷新重试。

### 4.8 本地数据与三天清理

消息、AI 摘要、要点、封面缓存及相关临时内容从首次成功保存起保留三天。达到期限后自动删除，不提供收藏、归档和恢复入口。

三天清理不删除：

- 订阅来源；
- 订阅起点；
- 平台登录会话；
- 增量刷新位置和去重所需的轻量标识。

为了防止清理后再次抓回旧消息，已清理内容的完整正文可删除，但其平台内容 ID 或链接指纹应至少保留到足以覆盖平台增量窗口。

### 4.9 错误处理

- 单个平台失败不得中断其他平台刷新。
- 网络错误、登录过期、平台限制、正文提取失败和 AI 调用失败使用不同提示。
- 刷新失败不清空已有消息，也不错误推进刷新位置。
- 刷新结束显示汇总，例如“新增 8 条，2 个来源需要重新登录，1 条处理失败”。
- 没有新内容时显示“暂无新消息”，不复制旧消息。
- 对平台限流采用有限退避，不无限重试，也不绕过验证码或平台安全机制。
- 专用 Edge 未安装、登录未完成或页面要求验证码时，停止该来源采集并提示用户处理，不降级为官网摘要。

## 5. AI 陪伴后续规划

本阶段仅保留网站内二级页面和“后续开放”说明。后续开发可拆成以下能力：

- 上传人物或宠物照片并生成桌面宠物外观；
- 上传或录制声音，在明确授权后生成对应声音；
- 支持待机、移动、点击回应、对话和情绪动作；
- 默认将素材和生成结果保存在本机；需要云端处理时明确提示上传范围；
- 支持彻底删除训练素材和生成角色；
- 要求用户确认拥有照片和声音的使用权，避免未经允许仿制他人身份。

该模块必须另行完成模型选择、隐私、安全、成本和桌面性能设计后才能进入实施。

## 6. 拓展功能与插件中心

本阶段建设独立插件中心和统一接入接口，不内置具体第三方业务插件。

插件中心展示名称、说明、版本、开发者、权限和启用状态，并支持安装、启用、停用和卸载。插件必须显式声明所需能力，例如：

- 网络访问；
- 文件读取或写入；
- 系统通知；
- 调用已有 AI 服务；
- 创建网站内二级功能页面；桌面窗口能力需另行授权和开发。

安装前向用户展示权限，未经授权不得访问对应数据。插件运行应与核心程序隔离，单个插件错误不能导致主程序或其他功能崩溃。

“今日消息”的平台适配器使用相似的接口思想，但属于内置采集适配器，不作为普通插件在插件中心随意卸载。第三方开发者后续可按照公开接口自行决定接入何种插件能力。

## 7. 开发顺序

1. 今日消息二级页面、订阅列表、消息卡片和现有 UI 组件复用。
2. 平台官方登录窗口、会话保存、失效检测和重新登录。
3. 统一采集适配器接口和增量刷新协调器。
4. 依次接入 B站、YouTube、抖音、小红书和普通网站适配器。
5. 复用现有大模型配置，完成摘要、重点和完整卡片呈现。
6. 完成去重、刷新位置和三天自动清理。
7. 完成插件中心骨架、权限声明和统一接口。
8. 保留 AI 陪伴入口与后续说明，不进入训练实现。

平台适配器应逐个交付和验收，不要求等待全部平台完成后一次上线。

## 8. 测试与验收

### 8.1 自动化测试

- 二级页面进入、返回及重复进入行为；
- 首次刷新边界，确保每个来源只展示最新 1 条且不批量导入历史；
- 后续刷新边界，确保只展示上次成功刷新后的全部新内容；
- 增量游标推进和失败时不推进；
- 平台内容 ID 与原链接双重去重；
- 多来源并行刷新和错误隔离；
- AI 返回结构校验、重试和未配置提示；
- 三天清理及关联缓存删除；
- 已清理消息不会在下一次刷新中重新出现；
- 插件权限校验和单插件故障隔离。

### 8.2 人工验收

- 所有新功能均进入网站内二级页面，不打开浏览器新页面或 Tauri 功能窗口。
- 二级页面与当前 UI 的颜色、字体、圆角、卡片、按钮和动效一致。
- 平台登录发生在官方页面，应用不保存账号密码。
- 第一次点击刷新后，每个来源的最新 1 条内容完成 AI 总结即显示完整卡片；后续刷新显示全部新增内容。
- 点击卡片可以准确跳转到原视频或文章。
- 单个平台登录失效或抓取失败不影响其他平台。
- 所有消息及相关缓存满三天后自动删除。

## 9. 风险与约束

- 抖音、小红书等平台存在登录验证、接口变化和访问频率限制，适配器必须允许独立替换，并遵守平台条款和适用法律。
- “实时信息”在本设计中指用户点击刷新时立即检查，不代表后台持续轮询。
- 无字幕视频的总结质量受可取得文本信息限制，不能保证等同于完整观看视频。
- 平台登录会话属于敏感本地数据，由 Edge 的持久化配置与操作系统账户保护；应用不得将 Cookie 明文复制到自身数据文件或前端存储。
- 插件扩展能力必须建立在权限隔离之上，不能允许第三方代码默认获得完整本机权限。

## 10. 完成定义

当“今日消息”可以通过网站内二级页面管理来源、完成官方登录、按点击刷新增量取得订阅后的新内容、复用现有大模型生成完整消息卡片、跳转原内容，并在三天后清理消息与缓存时，核心功能视为完成。

插件中心完成统一接口和权限骨架、AI 陪伴保持二级占位页面后，本设计范围内的第二阶段策划目标视为完成。
