# 桌面挂件交互与尺寸设计

## 目标

完善桌面挂件的窗口行为和业务交互：去除滚动条、支持从顶部拖动、按内容自动调整高度，并让 TODAY、添加待办和 TASKS 与网站中的真实工作区联动。

## 窗口行为

- 挂件模式同时为 `html` 和 `body` 添加独立状态，关闭横向与纵向滚动条并取消全局最小宽度。
- 顶部栏保留置顶与关闭按钮，其余区域标记为 Tauri 拖动区域；鼠标按住顶部空白区域即可拖到任意屏幕位置。
- 根据启用区块和实际显示条目数计算窗口高度。高度包含顶部栏、卡片标题、区块标题、条目、新增按钮和外边距，并限制在安全的最小值与屏幕可用范围内。
- 内容或配置变化后重新计算尺寸；窗口不通过内部滚动来容纳正常数量的项目。

## TODAY 联动

- 点击未完成待办后，通过 Tauri 原生命令读取最近使用账户的 `workspace-data.json`，将对应待办的 `completed` 更新为 `true`，安全写回文件。
- 命令成功后挂件立即刷新本地状态，因此该条目立刻消失。
- 写入失败时保留条目并显示可读错误，不假装完成。

## 新增待办与 TASKS 联动

- “新增待办”使用系统默认浏览器打开 `http://127.0.0.1:5173/?widgetAction=add-today`。
- 点击任务使用系统默认浏览器打开 `http://127.0.0.1:5173/?widgetTask=<任务ID>`。
- 网站启动时解析这些查询参数：`add-today` 切换到“今日待办”并打开新增窗口；`widgetTask` 切换到“任务清单”，在工作区数据加载完成后打开对应任务编辑窗口。
- 消费参数后使用 History API 清理 URL，避免刷新时重复打开。
- 桌面挂件不再显示或聚焦发布版 Tauri 主窗口，因此不会进入缺少本地 API 的登录页面。

## 数据与安全

- 原生命令只允许修改当前工作区文件中的 `todayTodos[].completed`，不接受任意文件路径。
- 任务 ID 和待办 ID 在写入 URL 前编码。
- 工作区写入采用临时文件后替换，降低中断造成数据损坏的风险。

## 测试与验收

- CSS/组件测试确认挂件模式无滚动条并存在顶部拖动区。
- 尺寸计算函数测试空内容、单区块和最大条目数。
- Rust 测试确认待办完成后写回 JSON，未知 ID 返回错误。
- 组件测试确认 TODAY 成功后立即消失，失败时显示错误。
- App 测试确认两个网站深链接分别打开新增待办和指定任务。
- 手动验证拖动、动态高度、完成待办、新增待办和打开任务全过程。

## 范围外

- 不在挂件内编辑任务详情。
- 不在挂件内新增完整待办表单。
- 不修复发布版主应用的完整认证和服务端能力。
