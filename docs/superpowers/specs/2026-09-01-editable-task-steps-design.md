# 可编辑任务步骤与进度设计

## 目标

将任务的步骤从数量字段升级为真实、可编辑、可完成的步骤列表，并由步骤完成情况自动计算任务进度与任务状态。

## 数据结构

```ts
type TaskStep = {
  id: string;
  title: string;
  hours: number;
  completed: boolean;
};

type Task = {
  // 现有字段
  steps: TaskStep[];
};
```

任务总预计时长由步骤小时数求和。最小粒度为 `0.25 小时`；允许 `0.25、0.5、0.75、1、1.5、2、3、4`，自定义值按 `0.25` 对齐。进度为已完成步骤数除以总步骤数；没有步骤时进度为 0。

## 创建与 AI 分析

- AI 输出格式使用 `estimatedHours` 和 `steps[].hours`，每步附带 `description` 与 `completionCriteria`。
- AI 必须使用简体中文、生成 2–8 个具体步骤、标题不超过 24 个中文字符。
- 步骤小时数之和必须严格等于 `estimatedHours`；单步骤超过 4 小时时继续拆分。
- 服务端校验总时长、小时粒度和空泛标题；首次格式错误时自动重试一次。
- AI 返回的步骤映射为带稳定 ID 和 `completed: false` 的步骤。
- 第二步分析结果中，步骤标题与小时数均为受控输入。
- 用户可新增、删除步骤；至少保留一个有效步骤。
- 手动分析模式创建默认步骤，数量来自任务默认值。
- 保存任务时写入用户最终确认后的步骤，而不是只保存数量。

## 任务清单气泡

- 每个任务卡片以可换行的圆角气泡展示步骤，不显示输入框。
- 气泡显示完成圆圈、序号、标题和小时数；点击圆圈或气泡切换完成。
- 已完成气泡使用弱化绿色背景和删除线。
- 勾选步骤后显示删除线并更新进度条。
- 所有步骤完成时任务自动完成；恢复任一步时任务恢复为进行中。
- 点击任务总完成圆圈会一次完成全部步骤；再次点击会恢复全部步骤。
- 任务统计“正在进行/已经完成”继续依据任务状态自动更新。

## 编辑箭头与窗口

- 右侧箭头只承担“编辑任务”，悬停和无障碍名称明确标注。
- 点击后打开完整编辑窗口，加载任务名称、内容、优先级和原步骤。
- 步骤标题在编辑窗口内使用文本输入；时间使用无上下箭头的小时选择器。
- 支持添加、删除和调整步骤顺序；至少保留一个步骤。
- 编辑已有步骤不得重建 ID 或重置完成状态。

## 编辑与兼容

- 任务编辑弹窗加载已有步骤，修改后覆盖原步骤。
- 旧任务若只有数字 `steps`，迁移为对应数量的“步骤 1…N”，每步平均分配原预计时长。
- 备份导入同时接受旧数字格式和新数组格式，导出只写新格式。

## 错误与边界

- 步骤标题为空时保留上一次有效标题。
- 小时值非法时恢复为 `0.25`，并对齐到 `0.25` 的整数倍。
- 删除最后一个步骤时阻止操作并显示提示。
- 步骤 ID 只在创建步骤时生成，编辑不得重建 ID。

## 验证

- AI 步骤在保存前可编辑；保存后通过箭头编辑窗口修改。
- 单步勾选只影响对应步骤。
- 完成数量、百分比、进度条和任务状态保持一致。
- 全部完成与恢复步骤可双向联动任务统计。
- 新旧任务和备份格式都能正确读取。
