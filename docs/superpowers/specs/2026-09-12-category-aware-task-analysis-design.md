# 分类感知的 AI 任务拆解设计

## 目标

AI 分析任务时先根据标题、说明、期望时长和注意事项判断任务大类，再采用对应的专属方法生成可执行步骤。用户无需手动选择分类，输出继续兼容现有任务卡。

## 任务分类与拆解逻辑

- 学习类：明确目标与产出 → 领域地图 → 系统资源 → 最小知识框架 → 问题驱动 → 输出倒逼输入 → 验证纠错。
- 开发/项目类：需求与验收 → 技术选型与调研 → 搭建环境 → 核心功能开发 → 联调与测试 → 部署与复盘。
- 写作/内容类：明确受众与目标 → 确定主题与大纲 → 收集素材 → 撰写初稿 → 修订润色 → 发布与反馈。
- 规划/准备类：明确目标与现状 → 收集信息 → 制定计划 → 执行准备 → 模拟预演 → 复盘调整。
- 生活/习惯类：设定具体目标 → 拆解微小习惯 → 设置触发条件 → 执行并记录 → 周度复盘。

## 输出与约束

- 保持现有 `summary`、`goal`、`priority`、`estimatedHours` 和 `steps` JSON schema。
- 每个步骤继续包含 `title`、`hours`、`description` 和 `completionCriteria`，以支持现有编辑、进度和验收 UI。
- 步骤名称必须包含任务领域的具体动作，避免“学习资料”“完成任务”等空泛表述。
- 步骤数量遵循用户设置的最少/最多步骤范围；总时长遵循用户填写的期望时长，并保持每步时长之和等于总时长。
- 服务端代理和浏览器直连使用同一分类规则、JSON 约束及重试修正规则。

## 错误处理

- 模型输出仍由现有 schema 校验；格式、时长或步骤不合法时重试一次。
- 无法明确分类时，选择最接近任务最终产出的类别，不向用户增加分类确认步骤。

## 验收

- STM32 学习任务生成学习类步骤，且包含官方资料、环境实践、输出与验证动作。
- React 修 Bug 生成开发类步骤，不套用学习领域地图。
- 写周报生成写作类步骤，不生成开发环境步骤。
- 两条 AI 调用路径生成相同结构且均能通过现有解析器。
