# 桌面挂件内新增与编辑设计

## 目标

桌面挂件中的“新增待办”和任务点击不再打开浏览器网站，而是在挂件内部显示覆盖式表单。保存后直接更新当前账户的工作区文件并刷新挂件。窗口拖动改由 Rust 原生命令执行。

## 新增待办

- 点击“新增待办”后，在挂件卡片上方显示覆盖式表单。
- 表单包含待办内容和可选提醒时间。
- 内容为空时禁止保存并显示提示。
- 保存通过限定范围的 Tauri 命令写入当前账户 `todayTodos`，生成唯一 ID，默认 `completed: false`。
- 成功后关闭表单并立即显示新待办；取消不修改数据。

## 编辑任务

- 点击 TASKS 条目后，在挂件内部显示任务编辑表单。
- 表单支持任务标题、说明和完成目标；步骤保留原数据，不在轻量挂件中编辑。
- 标题为空时禁止保存。
- 保存通过限定范围的 Tauri 命令只更新指定任务的上述字段。
- 成功后关闭表单并立即更新挂件中的任务标题；未知任务 ID 返回错误。

## 窗口与拖动

- Tauri 配置将挂件设为可聚焦，以支持输入框、键盘和原生拖动。
- 顶部拖动区的鼠标按下事件调用 Rust 命令 `start_widget_dragging`；Rust 使用当前 `desktop-widget` 窗口执行 `start_dragging()`。
- 顶部置顶和关闭按钮仍保持独立点击，不触发拖动。
- 打开表单时窗口高度加入表单所需空间，并保持无内部滚动条。

## 数据一致性

- 所有写命令只使用启动参数绑定的当前用户 ID，不接受任意文件路径。
- 写入使用现有临时文件、备份和替换流程。
- 命令返回更新后的完整工作区；React 以返回值更新本地挂件状态，避免等待轮询。

## 测试与验收

- 组件测试覆盖打开、取消、校验和保存新增待办。
- 组件测试覆盖打开、取消、校验和保存任务编辑。
- Rust 测试覆盖新增待办、更新任务和未知 ID。
- 服务测试覆盖三个原生命令及参数。
- 拖动测试确认顶部区域调用 Rust 拖动命令。
- 手动验证输入、保存、拖动、窗口高度和关闭行为。

## 范围外

- 不在挂件内编辑任务步骤、优先级或 AI 分析结果。
- 不再从挂件操作打开浏览器网站。
